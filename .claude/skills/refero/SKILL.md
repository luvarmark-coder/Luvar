# Refero — реальные UI-референсы

Refero — база скриншотов живых продуктов, разложенных по экранам, флоу и стилям.
Инструменты приходят от MCP-сервера `refero` (префикс `mcp__refero__*`).

## Проверка перед работой

Если инструменты `mcp__refero__*` недоступны — сервер не подключён. Скажи об этом
и дай команду для установки (выполняется один раз в корне проекта):

```bash
claude mcp add --transport http refero https://api.refero.design/mcp \
  --header "Authorization: Bearer <ТОКЕН>"
```

После этого нужно перезапустить Claude Code, чтобы инструменты подгрузились.

## Инструменты

### Стили — визуальный язык
- `refero_search_styles(query, page?, response_format?)` — семантический поиск дизайн-стилей.
  Возвращает превью: UUID, заголовок, исходный URL, картинку, описание визуального языка.
- `refero_get_style(style_id | style_ids, response_format?)` — полный стиль-гайд:
  цвета, типографика, типографическая шкала, отступы, радиусы, тени, поверхности,
  компоненты, ритм секций, работа с изображениями, do/don't, north star, сниппеты кода.

### Экраны — конкретная структура интерфейса
- `refero_search_screens(query, platform, page?, response_format?)` — поиск экранов.
  `platform` обязателен: `ios` или `web`.
- `refero_get_similar_screens(screen_id, limit?, response_format?)` — похожие экраны,
  чтобы развернуть одну удачную находку в подборку.
- `refero_get_screen(screen_id | screen_ids, response_format?)` — полные метаданные экрана.
- `refero_get_screen_image(screen_id, image_size?)` — сама картинка как MCP-image
  (`thumbnail` или `full`). Только так можно реально разобрать вёрстку глазами.

### Флоу — логика многошаговых сценариев
- `refero_search_flows(query, platform, page?, response_format?)` — поиск сценариев:
  онбординг, чекаут, регистрация, сброс пароля, отмена подписки, удаление аккаунта.
- `refero_get_flow(flow_id | flow_ids, response_format?)` — весь путь по шагам,
  с `goal` / `action` / `system_response` для каждого экрана.

`response_format`: `md` — читаемо для человека, `json` — когда нужно разобрать данные.

## Порядок работы

Проектируешь новый интерфейс с нуля — иди сверху вниз:

1. **Стиль** → `refero_search_styles` задаёт визуальное направление (шрифты, палитра, ритм).
   Взять 2–3 подходящих и раскрыть через `refero_get_style`.
2. **Экраны** → `refero_search_screens` показывает, как устроена конкретная страница:
   структура, иерархия, состояния, микрокопирайт.
3. **Флоу** → `refero_search_flows` даёт логику переходов, если сценарий многошаговый.

Правишь один существующий экран — начинай сразу с шага 2.
Нужен только «вайб» и цвета — хватит шага 1.

## Как формулировать запрос

Запросы семантические, поэтому описывай **задачу и контекст**, а не одно слово.

- Плохо: `dashboard`
- Хорошо: `аналитический дашборд SaaS с боковой навигацией и карточками метрик`
- Хорошо: `онбординг финтех-приложения с верификацией личности`
- Хорошо: `тёмный премиальный лендинг с крупной типографикой и градиентами`

Можно искать по компании: `как Linear делает настройки проекта`.

## Правила

- Всегда открывай `refero_get_screen_image` для экранов, которые реально разбираешь.
  Метаданные без картинки — слабое основание для дизайн-решения.
- Не вываливай сырой вывод инструмента. Собери 3–5 лучших референсов, по каждому
  скажи, **что именно** стоит забрать и почему это подходит текущей задаче.
- Пустой результат — переформулируй запрос шире (убери название компании,
  опиши задачу общими словами) и попробуй ещё раз, прежде чем сдаваться.
- Референс — не ТЗ. Адаптируй под проект, а не копируй один в один.
- Собираешься писать код по найденному стилю — сначала вытащи токены
  (цвета, шкала шрифтов, отступы, радиусы) через `refero_get_style`,
  и только потом верстай.
